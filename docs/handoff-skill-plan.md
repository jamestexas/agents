# Handoff-at-the-Seam Skill — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Author `skills/handoff/SKILL.md` — a rosary-anchored `handoff` skill with a `write` mode and a `--resume` mode, per `docs/ADR-003-handoff-at-the-seam.md`.

**Architecture:** A single instructional skill (markdown + YAML frontmatter). The skill orchestrates existing rosary MCP tools; it adds no code. "Machine truth" is a `rsry_agent_session_message_record` mailbox entry (`event_type=handoff_message`) with a structured payload; a `rsry_bead_comment` is the human trail; `rsry_workspace_checkpoint` snapshots the tree; a `/tmp` markdown file is the human-grab view. `--resume` drains the mailbox and re-validates live state.

**Tech Stack:** Markdown skill authoring (Claude Code skill format), rosary (`rsry_*`) MCP tools, `scripts/build.sh lint` (frontmatter validator + MCP-dependency-declaration check), README table regeneration.

**Source of truth:** `docs/ADR-003-handoff-at-the-seam.md`. This plan references ADR sections rather than re-inlining their prose. **Bead:** `agents-a40691`.

**Verification model (read this first):** There is no unit-test framework for prose skills. Each task's "test" is one or more of:
- `bash scripts/build.sh lint` exits 0 (frontmatter valid + `**MCP dependency:**` declared because the skill calls `rsry_*`).
- `grep` confirms a required section/instruction is present in `skills/handoff/SKILL.md`.
- Manual read-back against the named ADR section.

```markdown
## 0. Resolve mode
If `$ARGUMENTS` begins with `--resume`, go to §5 (RESUME). Otherwise this is a WRITE handoff; continue.

## 1. Resolve the seam (WRITE)
The mailbox entry needs one anchor bead. Resolve it by this precedence — **detection proposes, the human confirms; never anchor silently** (except rung 1, already named):

1. **Explicit** — if `$ARGUMENTS` starts with a bead id (e.g. `agents-a40691`), that is the seam. Use it.
2. **Detected spine** — otherwise infer the spine bead, in order:
   a. active dispatch — `rsry_active` / `rsry_dispatch_history`
   b. current jj bookmark / git branch — `jj bookmark list` or `git branch --show-current`, matched against open beads
   c. most-recently-touched bead — `rsry_bead_history`
   Present the resolved seam to the user and get a one-tap confirm before writing.
3. **Minted** — only if all three detectors return nothing or mutually disagree (ADR §12.1): mint a seam with `rsry_bead_create(issue_type=research|design, title="handoff: <slug>", acceptance_criteria=<the one-sentence task>)` and link the in-play beads via a `discovered-from` dependency.

Record the chosen rung as `seam.resolution` in the payload (§4). Collect satellite beads into `seam.related`.
```

```markdown
## 2. Bootstrap from state (WRITE)
Reconstruct what happened from rosary BEFORE summarizing from the conversation — so the handoff survives compaction:
- `rsry_bead_history <seam>` — what changed on the bead this session.
- `rsry_dispatch_history` — which agents touched what.
- `rsry_agent_run_events` — prior events on the bead.
Use the conversation only for the glue rosary cannot see: the *why*, dead ends, judgment calls.

## 3. Derive scope from the task verb (WRITE)
Restate the task in ONE sentence from `$ARGUMENTS` (the invocation), NOT from where the session sits.
- "find out / investigate / determine / check" → `task.deliverable = report` (NO recommendation, chosen fix, or plan).
- "implement / fix / add / migrate" → `task.deliverable = change`.
This becomes a typed field in the payload and is restated at RESUME, so scope creep is caught at pickup.
Proofread gate: re-read every field against the one sentence; cut anything that does not serve exactly that task.
```

## Task 5: RESUME mode — drain + re-validate (ADR §5, §12.2)

**Files:**

- [ ] **Step 1: Append the RESUME section**

```markdown
## 6. RESUME (`--resume [<bead-id>]`)
1. **Drain** — `rsry_agent_run_events` filtered to `event_type=handoff_message` for the repo (and bead, if an id was passed). Take the latest; read its `payload`.
2. **Land on the tree** — if `payload.state.checkpoint` is set, check out that jj change so the working tree matches the handoff.
3. **Re-validate live state** — the mailbox entry is an OBSERVATION at handoff time, not current truth. Run `rsry_status` + `rsry_expand_ref <seam>` (or `rsry_list_beads`). If the seam bead is `closed` or reassigned, **HARD-STOP** and print a drift report (ADR §12.2) — do not silently resume. The human decides: reopen, re-anchor, or abandon.
4. **Restate & begin** — restate `payload.task.one_sentence` and `payload.task.deliverable`; honor the deliverable class (a `report` handoff must not start making changes). Load any `payload.suggested_skills`. Begin.
```
